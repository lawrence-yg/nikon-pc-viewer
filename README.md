# 尼康优化校准查看器

拖入优化校准文件，查看它的色调曲线与各项参数。全中文，单文件，双击即用。

## 用法

直接双击 `index.html`。不需要联网，不需要安装任何东西。

1. 把 `.NCP` 或 `.NP3` 文件拖到页面上 —— 左边显示色调曲线，右边显示中文参数
2. **手头没有文件？点页面上的内置示例按钮**，三个都是真实可解析的文件：
   - **Filmic S 曲线**（NP3）—— 暗部压暗、高光滚降
   - **重色彩**（NP3）—— 色彩混合与色彩分级拉满
   - **柔和反差**（NCP）—— 尼康早期格式的示例
3. **「解读」卡 + 色彩色块卡**用短句和色块说明这条配置在做什么。**色彩详、明暗略**——
   有色彩数据时枚举全部有调整的色系（方向词，如"蓝更艳更暗"）、
   分离色调带各段强度与混合/平衡数值；明暗只留一句**原型归类**
   （标准S形 / 哑光型 / 暗部裁切型 / 非单调…，非单调会得到色调断层警告）。
   **色彩混合/分级折叠卡放在左栏曲线图与照片预览之间**（默认折叠，空间利用率：
   右栏只留解读与基础），
   合并为一张折叠卡——**默认折叠，点标题整组展开/收起**，状态在切换文件后保持；
   **五锚点表**（0/25/50/75/100 的输出值 + 各段实际斜率）在左边曲线图的图例下方。
   句子全部由确定性规则生成，不调用任何模型；每个维度只有一条互斥规则，
   省略优于猜测。细节见 `src/describe.js` 顶部注释。
4. 想看效果的话，往下拖一张自己的 JPG，可以左右拖动分隔线对比

## 支持情况

| 格式 | 状态 | 说明 |
|---|---|---|
| `.NCP` | ✅ 支持 | 尼康早期机型（放进存储卡 `custompc` 文件夹导入的那种） |
| `.NP3` | ✅ 支持 | NX Studio 的柔性彩色优化校准 |
| `.NP2` | ⚠️ 识别但不解析 | 拖入会提示「签名已识别，解析尚未支持」，不会误报成坏文件 |

两种格式**共用同一个 `NCP\0` 容器**，靠记录结构区分：NCP 是定长记录（首个记录 id=1、长度 36），NP3 是带 tag 的记录（首个 id=0x00000100）。解析时也会实测校验，避免误判。

NP3 依赖 [ssssota/nikon-flexible-color-picture-control](https://github.com/ssssota/nikon-flexible-color-picture-control)（MIT，已内联，无外部依赖）。NCP 解析依据 [tvgenious89/nikon-pc](https://github.com/tvgenious89/nikon-pc) 的公开逆向资料，并用其测试夹具中的真实样本验证过。

## 三种格式的关系

它们确实是同源的，共用 `NCP\0` 容器，而且 **record 2 的曲线段结构完全相同**（都是 256 项、32767 刻度的查找表）。差别在于：

- **NCP** 字段少：只有锐化、饱和度、色相等基础调节量 + 一个基准优化校准（标准/中性/鲜艳/人像/风景/单色）
- **NP3** 多出 **色彩混合（Color Blender，八个色系）** 和 **色彩分级（Color Grading，三段）** 这两组分色域调色
- NP3 的数值用四分之一档编码：`(值 − 0x80) / 4`

## 关于照片预览，请务必知道

预览分两层，可信度不同：

- **色调曲线：精确**。预览把查找表直接作用在 sRGB 字节上，跟曲线图一一对应
  （图上第 i 格多高，预览就把 i 变成多少），所见即所得。但相机是在它自己的处理域里
  套曲线的，数值上不等价。
- **色彩（仅 NP3）：示意近似**。色彩混合按色相距离加权调整饱和度/亮度
  （灰像素没有色系归属，不受影响）；色彩分级按亮度三区染色（灰正是被染的对象）；
  整体饱和度直接乘算。**方向来自文件参数，幅度是约定换算——尼康没公开算法，
  和相机直出会有明显差别。**色彩混合的色相偏移方向（±100 对应往哪转）依然没有模拟。
- **重复施加警告**：相机直出的照片已经套过一次风格，在这里再套会重复施加，
  请用尽量中性的原片。
- 对比度、锐化、白平衡、色域映射：没有被模拟。

## 几个容易误解的点

**NP3 含自定义色调曲线时，对比度／高光／阴影／白位／黑位会是 0。** 这是格式规定，不是解析错误。但**没有**曲线的 NP3 文件这些值是正常的。

**NCP 的对比度和亮度读不出来。** 该格式在这两个位置存的是标志位而非数值，实际由色调曲线承担。工具里会明确说明。

**单条色调曲线表达不了颜色变化。**「色彩混合」「色彩分级」是分色域调色，看曲线图时颜色部分要对照右边的参数面板一起看。面板里这两组用**色块示意**呈现（基准色 → 调整后）：
- 色彩混合的色块只画**艳度和明度**变化——色相是 ±100 的偏移量，尼康未公开它对应的角度与方向，所以色块不体现色相偏移，方向看数值，不猜
- 色彩分级的色相是 0~360 绝对值，色块直接画出各亮度区段被染上的颜色（灰 → 目标色）

**控制点和查找表可能对不上。** 真实样本 `Horshack_Linear.NCP` 的控制点只有 `0→0`、`255→255` 这一对端点，
看着像恒等曲线，但同一记录里的 256 项查找表明显压暗（与恒等最大偏差 54）。图里画的是查找表，
相机执行的也是查找表，所以文件名里的「Linear」不能按字面理解。界面上遇到这种情况会直接写明。

**NCP 的调节量是半格也可能。** 每格 = 4，但真实样本里出现过 130 这种值，也就是半格；
工具保留小数并同时给出原始字节，不会把它取整夸大成「+1」。

## 开发

```bash
npm install
npm run fetch-samples   # 下载公开的真实 NCP/NP3 样本（交叉验证用）
npm run samples         # 生成内置演示样例（build 会把它们内联进 HTML）
npm test                # 四个 node 侧检查：真实样本、内置样例、非法输入、解读句合成曲线断言
npm run build           # 内联成单文件 HTML
npm run ui              # 用 headless Chrome 跑界面断言（可用 CHROME=... 指定浏览器）
npm run shot            # 载入内置示例后出一张 PNG，给人眼复核用（node shot.mjs filmic|color|soft 宽,高 [img]）
npm run check           # build + test + ui 一遍过
npm run serve           # 本地起服务调试（首页即构建产物，http://127.0.0.1:8791）
```

改代码只动 `src/` 下的文件，改完跑 `npm run check`。

`test-reject.mjs` 盯的是这类事故：NP3 解析库（vendored，未做修改）对任意缓冲区都**不会抛错**，
越界处读出 `NaN`、名称读出乱码，早先版本因此会把拖进来的 JPG 当合法文件展示，界面里一句错误都没有。
现在 `parseAny()` 先要容器签名 `NCP\0`，再按首个记录 id 分派（NCP=1，NP3=0x00000100），
NP3 还要求名称字段是可打印 ASCII —— 过不了就报错，绝不猜。

`ui-check.mjs` 里「预览就是图上那条曲线」这条断言盯的是另一类事故：预览一度在查表前多做了一次 sRGB 解码、
查表后却没换回去，于是套出来的结果和图上画的完全对不上（输入 100 出 47，而图上明明是 109）。
现在两边共用同一张查找表，断言直接拿像素比对 `lut[输入]`。

`test-describe.mjs` 盯的是解读句的事故（第一版自然语言试验真实翻车过）：
矛盾句（"高光有过渡"与"高光直通到顶"同现）、越界值（"亮部从 251% 开始滚降"）、
负百分比（"超过 -1% 才到纯白"）、交点检测全错（连 S 曲线都报"无交点"），
以及概念错误（用偏移描述本该用斜率描述的 S 曲线中间调）。
现在的结构约定：每个维度只有一条 else-chain 规则（互斥是结构性的，不靠事后检查）；
百分比输出前夹取到 0~100，测不出来就整句省略；
量化台阶导致的单级斜率虚高用 ±4 级滑动平均压掉；
测试用已知参数的合成曲线断言"测量→还原"（S 曲线肩部解析解 91%，实测 91%）。

**解读的有意取舍**：阈值在 0~255 码值空间调定，没换算到 L* 感知均匀空间
（更简单、可测；尼康自己的刻度也不是 L*，若将来要更严谨可作升级项）。
反差 = 输出标准差与均匀分布标准差之比；"死黑/顶白"要求连续 ≥8 级贴死
（S 曲线过原点的两三级小台阶不算）；色彩混合的色相方向永不描述（±100 对应角度未公开）。

`samples/` 里的 `demo-*` 是内置示例（`make-sample.mjs` 生成），`Horshack_Linear.NCP` 和 `ClrMode_Bu_01a.NP3` 是从公开仓库下载的真实文件，仅用于验证解析器，不内联进产物。
内置示例「柔和反差」原来的曲线其实是加反差的 S 形，跟名字相反，现在改成了真正的低反差（黑位抬起、白位压住）。
